# UI Spec for AI

**给 AI 写前端的 UI/UE 规范与动效知识库。**

把设计规范写成模型能执行、人能验收的条款：184 条带编号的规则、39 项交付验收，覆盖设计令牌、布局、组件、动效、无障碍与文案。

[规范正文](./spec.md) · [快速开始](#快速开始) · [三种用法](#三种用法) · [文档地图](#文档地图)

> English: A Chinese-first, executable UI/UX and motion specification for AI-generated frontends. It ships 184 numbered clauses, 39 acceptance checks, and 5 prompt templates. English translations and clause-level discussions are welcome.

---

## 为什么需要它

AI 能在几十秒内生成一个页面，但默认输出往往长得很像：紫蓝渐变、emoji 图标、每张卡片都是大圆角大阴影、只做 happy path、全站共用一条缓动曲线。

设计规范通常写成散文。模型抓不住重点，评审也没法逐条对照。

这个仓库把两套来源重写成 184 条带编号的条款。条款区分「必须」与「建议」，并尽量给出可验证的数值：按钮高度 40、正文对比度 ≥ 4.5:1、常规过渡 ≤ 500ms。模型可以按条款生成，人也可以按条款验收。

## 它是什么，不是什么

| 它是 | 它不是 |
|---|---|
| 一份可执行的 UI/UX 规范 | 组件库或前端框架 |
| 184 条可引用的条款 + 39 项验收 | 设计灵感合集 |
| 5 个可直接复制的提示词模板 | 某个产品的设计系统 |
| 与模型、工具无关的纯文档 | 绑定 Claude Code / Cursor / Codex 的插件 |

## 快速开始

三步，不需要安装任何东西。

**1. 拿到规范**

把 [spec.md](./spec.md) 放进项目，或直接上传给 AI。

**2. 让 AI 按规范生成**

```text
请阅读 spec.md，并严格按《AI 前端 UI/UE 规范与动效知识库》生成「个人博客首页」（Web）。
先输出四份清单：令牌、布局、组件与状态、动效；然后给单文件 HTML + 内联 CSS。
生成后逐条核对 §8 的 CHK-01~CHK-39，不通过就先修正。
```

**3. 验收**

把生成结果和规范一起发回给模型：

```text
按 spec.md §8 逐条评审上面的页面。每个问题给出条款 ID、代码位置和具体改法，最后按 P0/P1/P2 排序。
```

第一次用，建议从 §9.1 的整页模板开始。它已经把四份清单、代码要求和验收步骤写进了提示词。

## 三种用法

### 生成新页面

```text
你是资深 UI/UE 设计师兼前端工程师。请严格按 spec.md 生成「订阅确认页」（Web）。
先输出：令牌清单、布局说明（视觉块 / 主轴线 / 375 与 1440 的变化）、组件与状态清单、动效清单（场景 / 时长 / 曲线）。
再输出单文件 HTML + 内联 CSS，必须包含 §1.6 的 :root 变量与 MO-28 的 prefers-reduced-motion 块。
最后逐条核对 §8，未通过项先修正再交付。
```

### 审查或改造已有页面

```text
按 spec.md §8 评审下面的页面，逐条判定「通过 / 部分 / 不通过」。
每个问题给出：条款 ID、代码位置、具体改法（数值、文案或参数）。
不要重做视觉概念，只做令牌对齐、状态补齐和动效收敛。
```

改造时用 §9.4 的模板，顺序是：先诊断，再令牌化，再补空/加载/错误态，最后收敛动效。

### 作为 agent 的项目规则

把下面三行放进 `AGENTS.md`、`CLAUDE.md` 或 `.cursor/rules/`：

```markdown
- 前端代码必须通过 spec.md §8 的 39 项验收。
- 颜色只能引用 §1.6 的 :root 变量，禁止在组件内写死色值。
- 新增动效必须写清时长与曲线，并提供 prefers-reduced-motion 降级。
```

整个文件 50KB，会占掉不少上下文。按任务只喂相关章节：

| 任务 | 只读这些 |
|---|---|
| 生成新页面 | §1.6、§3、§8 |
| 实现动效 | §4、§8.4 |
| 评审 / 改造 | §7、§8、§9.5 |

## 怎么引用条款

编号是稳定接口：`T-14` 指字号档位，`CP-16` 指提交失败的处理，`CHK-29` 指正文对比度。Issue、PR 和代码注释里可以直接引用编号，不必贴原文。

前缀含义：`T` 令牌 · `L` 布局 · `CP` 组件 · `MO` 动效 · `A` 无障碍 · `TX` 文案 · `AP` 反模式 · `CHK` 验收。

条款冲突时按 §1.1 的优先级处理：你给的品牌色或风格 > 默认色板；语义色和对比度不可覆盖。

## 定制品牌色

只改 §1.6 `:root` 里的四行：

```css
--brand-50:  #eaf6fe; /* 同色相浅底 */
--brand-500: #33acfb; /* 主色 */
--brand-600: #199be8; /* hover，约深 8% */
--brand-700: #1487cc; /* active，约深 16% */
```

不要在组件里写死色值。状态色（成功 / 警告 / 错误 / 提示）不随品牌换。颜色总数守住「1 主色 + 1 强调色 + 4 状态色 + 5 中性阶」。
